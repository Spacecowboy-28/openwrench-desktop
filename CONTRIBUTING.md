# Contributing

Read DEVELOPMENT_STATUS.md before starting. Work on one roadmap milestone at a
time. Create `dev/<topic>` branches and submit small pull requests. Run tests,
the source build and the native smoke test before proposing a merge.

Include the reason for the change, resulting behavior, tests and limitations.
Do not add inert buttons or advertise unfinished capabilities. Keep unsupported
functions outside release navigation. Keep application code independent of
particular makes, models and model years.

Submit only original work or appropriately licensed material. Record upstream
version, source, license, attribution and integration method. Never contribute
private VINs, personal records, API keys, service-manual scans without rights, or
manufacturer-specific values without provenance. Public example profiles contain
no ownership information.

MIT covers original code contributions. Data contributions require an explicit
license and source verification. The milestone-3 validator must exist before
accepting technical-specification datasets.
